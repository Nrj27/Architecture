# Contributing

Thanks for helping improve this architecture reference.

## What belongs here

- Clear, technology-neutral architecture guidance.
- Mermaid diagrams that render correctly on GitHub.
- Documented trade-offs and operational considerations.
- Examples that improve understanding without claiming to be universal solutions.

## Pull request checklist

- [ ] The change has a focused scope.
- [ ] Mermaid diagrams render on GitHub.
- [ ] New terminology is explained.
- [ ] Links and relative paths were checked.
- [ ] Security and failure behavior were considered.
- [ ] An ADR was added or updated when a design decision changed.

## Style

Use concise headings, descriptive link text, and tables for component catalogs. Prefer principles and trade-offs over vendor-specific recommendations unless the scope explicitly requires a vendor.
